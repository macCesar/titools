# SDK 14 Completions and class compatibility

PurgeTSS 7.20.2 builds its utility catalog from Titanium SDK **14.0.0.GA** Completions. The SDK refresh introduced in 7.20.0 added 63 property entries and restored 356 previously empty descriptions compared with 7.19.0; that initial catalog added 18 property families. These are catalog changes, not a requirement to upgrade every existing app to SDK 14.

The generated [property index](class-index-properties.md) and [categories](class-categories.md) reproduce what PurgeTSS emits. A class appearing there does not establish that the property is writable, available on every platform, accepted on every component, or supported by an older SDK. Check the installed SDK's API contract and the generated TSS value before recommending it. A dash in the index's Platform column means the selector has no platform condition; it does **not** certify cross-platform support.

## Published catalog and 7.20.1 corrections

The indexes shipped with this skill reproduce published **PurgeTSS 7.20.2**: 23,449 unique classes and 593 properties. Published 7.20.0 originally emitted 23,805 classes and 638 properties. Upgrade to 7.20.1 and regenerate the project's utilities before relying on the corrected forms. The release bundles Completions regenerated from SDK `api.jsca` through the corrected extractor, with the existing descriptions retained; the input is not edited by hand.

## Generated classes that need special care

### Scene state is read-only

The SDK marks SceneProxy `isActive`, `isForeground`, `isPrimary`, and `isKey` read-only. Read these values from the scene; do not use the old generated classes to try to change scene state. The Completions bundled in 7.20.0 marked these entries writable because the v3 extractor in `titanium-editor-commons` inverted `permission === 'read-only'` into `permission !== 'read-only'`. The SDK 14 `api.jsca` itself has the correct permission. The corrected extractor fixes the global flag and its duplicate-name merge.

PurgeTSS 7.20.1 reads `readOnly === true` and omits every such property from generated utility families and glossary pages; it does not maintain a new per-SDK list of state names. The release bundles input regenerated by the corrected extractor, preserving all fields other than the corrected flags. A shared name remains eligible when any occurrence is writable; that global flag does not make it writable on every type. If replacing this bundled input with an older extension-generated file, regenerate it through the corrected extractor first: an input with inverted flags is unsuitable for this filter.

### SplitWindow widths are not interchangeable

Published 7.20.0 used its spacing scale for these three width families:

```tss
'.primary-col-w-fraction-1': { primaryColumnWidthFraction: 4 }
'.primary-col-w-fraction-1/2': { primaryColumnWidthFraction: '50%' }
'.minimum-primary-col-w-16': { minimumPrimaryColumnWidth: 64 }
```

The SDK contract for `primaryColumnWidthFraction` is a **Number ratio**, not a spacing distance or percentage string. For published 7.20.0, use a direct numeric property such as `primaryColumnWidthFraction: 0.5` in an iOS-specific style or controller.

PurgeTSS 7.20.1 gives the ratio a separate scale: `primary-col-w-fraction-1/2` emits numeric `0.5`, `primary-col-w-fraction-1` and `primary-col-w-fraction-full` emit numeric `1`. Fraction suffixes are converted to numeric ratios, never percentage strings. The minimum/maximum families use numeric points (for example `minimum-primary-col-w-16` emits `64`); their percentage, `SIZE`, `FILL`, and `'1px'` variants are omitted. All three families carry `[platform=ios]`. Custom theme ratios must be finite Numbers from 0 to 1, and bounds must be finite nonnegative Numbers in points; invalid values stop generation instead of replacing the utility output. Use `theme.primaryColumnWidthFraction` to replace its scale or `theme.extend.primaryColumnWidthFraction` to add values. See the [numeric configuration example](customization-deep-dive.md#splitwindow-ratios-and-column-bounds-7201) for all three properties.

The resulting ratio width is limited by `minimumPrimaryColumnWidth` and `maximumPrimaryColumnWidth`.

`displayMode` and `splitBehavior` request a layout; the actual layout may differ with available width. Supply `masterView` and `detailView` before opening a SplitWindow. `presentsWithGesture` defaults to `true`. Class support does not replace these setup requirements.

### Deprecated SplitWindow controls still appear in the catalog

SDK 14 makes `showMasterInPortrait`, `masterIsOverlayed`, `masterViewVisible`, `portraitSplit`, and `landscapeSplit` ineffective. Their generated classes remain in the index for fidelity and older SDK projects. For SDK 14, use `displayMode`, `splitBehavior`, `showMasterView()` / `hideMasterView()`, and `primaryColumnWidthFraction`, respectively. Do not treat a clean unused-class check as proof that a deprecated property has an effect.

### Window bar settings have an OS requirement

SDK 14 documents `verticalBarBehavior` and `verticalBarCompressionBehavior` for iOS 27.1 or later. Configure the content Window when it is hosted by a NavigationWindow or TabGroup. Compression only matters inside those containers when a vertical bar is actually shown. Preserve an appropriate OS/version branch rather than assuming `ios:` alone establishes availability.

## Upgrade and verification

1. Check `purgetss --version` and the app's selected Titanium SDK. Use the [migration guide](migration-guide.md) for Node requirements and changes from 7.18/7.19.
2. Run PurgeTSS in the Alloy project so generator signatures invalidate old utility output. Do not edit generated `utilities.tss` or `app.tss` by hand.
3. Verify each proposed class in the project's `purgetss/styles/utilities.tss`, including its value, component and platform condition.
4. Inspect the end of `app/styles/app.tss` for unused classes and platform conflicts, then compile with the selected SDK. Generated text checks do not establish device rendering.
