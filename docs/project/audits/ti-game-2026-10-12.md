# ti.game skill audit 2026-10-12

The skill entrypoint and all nine existing references were reviewed, then a
reusable [physics reference](../../../skills/ti-game/references/physics.md) was
added. The 34-demo catalog remains the source for example selection; recipes
provide application patterns, and physics.md owns equations and units.

Upstream `m1ga/ti.game` HEAD was checked through git ls-remote and the GitHub
commit API: `3bea2f4007d4aa515e432ec2a016dd14c5c0f2ba` remains current.
Source verification uses that commit, independently from the macCesar fork's
local native edits. [Source hashes and evidence](ti-game-2026-10-12.json)
record 50 pinned files, including all 34 demos. The module working tree was
preserved; its earlier recorded source hashes still match.

## Findings and disposition

| Finding | Evidence and effect | Skill change |
| --- | --- | --- |
| Equations were scattered or absent | Model choice existed, but exact car, damping, impulse, integration and constraint formulas were difficult to retrieve | Added physics.md, with Engine/Demo/Analytical labels and routing |
| Powered motion can be erased by rest cutoff | Both Sprite twins apply damping after thrust and stop speeds below4px/s; a220px/s² launch at60FPS is erased | Documented equation, reproduction and the difference between coasting-only damping and a native rest-policy correction |
| Rope pause and damping limits were underspecified | Per-update retained displacement and constraints execute at zero dt | Qualified timeScale claims in API, recipes, patterns and roadmap; documented formulas and source boundary |
| Rhythm subdivision terminology was wrong | At the stated150BPM,400ms is a quarter note;1.6s is four quarters | Corrected recipe, catalog guidance and reference; prepared a separate three-comment upstream patch |
| Lander classified touchdown using post-response velocity | The native solid response can zero velocity before land; the old recipe accepts a400px/s arrival when live vy is0 | Replaced the recipe's measurement with solidimpact's snapshotted, compensated normal speed on a static sprite pad; documented limitations |
| Wind recipe nudged velocity from JS | gravityX already supplies native horizontal acceleration | Uses native gravityX when wind changes |
| Fuel rate lacked a time unit | Per-80ms subtraction obscured units and pause behavior | Explicit per-game-second rate on a game-clock cadence, with delayed-timer approximation disclosed |
| Topdown diagonal was faster | Recipe assigned full SPEED to both axes, unlike upstream normalized movement | Divides diagonal axis speed by sqrt(2) |
| Demo count differed between references | Launcher/catalog contain34; project-setup said33 | Corrected setup and excluded launcher/helper from count |
| TileLayer guide blamed an old README claim | Pinned README now correctly describes creation-only portable grid inputs | Corrected source attribution; portable contract unchanged |
| iOS simultaneous-input boundary was implicit | Existing pattern already uses Label, but UIKit UIButton exclusivity was not explained | Documented SDK13.4.1.GA internal exclusiveTouch and target-type distinction |
| Multiple iOS GameViews can replace controller callbacks | Pinned TGGamepadController assigns and clears one shared valueChangedHandler | Documented input ownership caveat in API/setup; local adapter fix is not called upstream support |
| Retained iOS backdrop can be permanently shut down on detach | didMoveToWindow invokes terminal renderer teardown | Documented attached-view/fresh-GameView choices and need for UIKit/device verification |
| Restitution1 was described as perpetual bounce | Small-rebound cutoff can still settle a body | Qualified the ball-sports recipe |
| Flappy replacement was described as additive impulse | The demo assigns vy=FLAP on each input | Clarified velocity replacement and its control implications |

These changes correct the skill and represent native limitations. They do not
change engine semantics, game balance, installed module binaries or assets.

## Verification

- Independent retrieval baseline, using only the original skill, identified
  missing exact equations and unsupported pause guarantees. The updated skill
  answered the same model/damping/Rope/Rhythm scenarios. A remaining car-equation
  gap was found during that test and corrected before the final green review.
- Two recipe checks executed the documentation's actual JavaScript blocks:
  diagonal magnitude350px/s and static-pad impact400px/s at H540, with live vy0.
  Both failed before edits and pass after. The safe touchdown20px/s case passes.
  The fixtures stub platform/effect boundaries; they do not run collision scenes.
- The original Java Rope.update method was extracted unchanged into an
  initialized scalar fixture. At dt0, node(10,0) with previous(10,−1),
  damping0.985 and link length10 becomes(9.951838,0.980256) after relaxation.
  This proves movement in that method; it is not an iOS/device renderer test.
- The thrust/gravity/damping/position expressions from TGSprite.update were
  compiled in C with equivalent scalar fields. Six cases cover thrust100/220
  at30/60/120FPS; the damped launch is erased at60/120 and damping0 starts it.
  Native source order was compared between Android and iOS.
- 408/408 TiTools tests pass with the asset-helper Python environment.
  Lint, skill quick validation and diff whitespace checks pass.
- All169 local skill links/anchors resolve, all89 JavaScript blocks parse,
  fences close, and the link checker rejects deliberate missing-file/anchor
  controls. The long-reference TOC is generated and a repeated dry run is unchanged.
- The canonical installed skill symlink resolves to this checkout.
  Version/package/plugin/CLI machinery was not changed; no sibling port is needed.

## Upstream recommendation

Rhythm supports a small comment-only PR. The [draft and patch](ti-game-rhythm-pr.md)
preserve runtime constants; comments removed from both versions leave identical
source. `node --check` accepts the corrected file and `git apply --check`
accepts the patch. No PR or maintainer message has been sent.

The damping cutoff and zero-delta Rope behavior are separate native findings.
Each deserves an isolated proposed policy, Android/iOS regression cases and
review. Existing local collision/gamepad changes must remain out of unrelated
proposals. The view/controller ownership findings likewise need their own scope.

Actual audio tempo, synchronization phase, native scene performance, complete
Rope pause UX and target-device acceptance remain unverified. A wrong musical
comment is not evidence of a faulty native beat scheduler; Rhythm has no such
audio-clock scheduler in its source.
